Other users

When the message that started you contains "For: <user id>", this run is for another Sift user, not the owner. Do every step above with these changes, and use only that user's own data under u/<id>/ in the app's database (same app url). Privacy: never mix two users' data, never copy a user's data outside u/<their id>/, never read the owner's Fit rules, About me or any of her Google Docs for a user, never write to any Google Sheet (the app keeps each user's own sheet), and never put names or answers in push notifications, the final reply or the improvement note (say "the user").

 - Never use Claude in Chrome for a user (it is the owner's own signed-in browser): read ads with WebFetch and web search only, skip 3c and 3f, and when no copy shows the responsibilities, decide "Check manually" with the reason.
 - Limit: read u/<id>/config/daily ({"date": UK "YYYY-MM-DD", "reviewed": n, ...}; a different date means 0). Review at most 8 minus today's "reviewed" jobs. At the end "set" it with today's date and reviewed increased by the jobs you decided (keep the other counts).
 - Step 1: the jobs come from ArtifactData "list" collection "u/<id>/feed" (query limit 1000, out_dir), not the sheet: jobs whose "decision" is empty, newest "dateFound" first.
 - Step 2: a. settings and facts from collections "u/<id>/search" and "u/<id>/me". b, c and d: ArtifactData "get" collection "u/<id>/about", doc_id "me": "learned" (rules the user gave by answering questions) wins, then "fitRules" (their fit rules) replaces the Fit rules doc, and "text" is the only source of facts about the user. Answers in a job's "note" count as in e.
 - Step 3e train check: only when the user's Home is set and "Gets to the office by" is "Train only (no driving licence)" or "Public transport" (search the web for a route; never invent times).
 - Step 4: "Shortlisted" means a role from their settings, the right level, a work pattern from their settings or not stated, a workable commute where needed, essentials they meet and the work their fit rules ask for. The "4 kinds of work", "Entrepreneurial" and Easy Apply parts are the owner's only. Shortlisted reason: the main reasons it fits in one line, plus the commute or "Remote" / "work pattern not stated".
 - Step 5: skip the sheet and the Jobs tab. 5b: "update" each decided job in collection "u/<id>/feed" (fields decision, reason, requirements, and salary or link if changed).
 - Progress points go to "u/<id>/progress", the Stop check reads "u/<id>/config" doc "running", the run log goes to "u/<id>/runs".
 - Step 6 hand-over: if any job was shortlisted and the user still has CVs left today, "set" u/<id>/config/running to {"step": "cvs", ...} and fire_trigger "<CV_TASK_ID>" with text "For: <id>. Run id: <new run id>". Otherwise "delete" u/<id>/config/running if its runId is this run's.
 - No push notifications for a user's run (there is no Chrome, so no human verification), except one "Sift shortlist error: database" if the database can't be written at all. The note's prefix is "Sift users shortlist note: ".
